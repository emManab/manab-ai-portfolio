## Identity kit

### Typography
- Headlines / interface: **Manrope**
- Metadata / technical labels: **DM Mono**

### Color system
- Paper: **#F8F5ED**
- Ink: **#0B0C10**
- Blue: **#5D72FF**
- Lime: **#B8FF4A**

Paper + ink form the foundation. Blue is for interaction/navigation; lime is reserved for emphasis/status.

### Shape, layout and motion
- Reading width: approximately 1180px
- Generous whitespace
- Controlled rounded corners
- Thin borders and restrained shadows
- Dense/quiet section rhythm
- Subtle entrance and hover motion
- Reduced-motion support

### Logo / favicon
The navigation uses the **MANAB.** wordmark. A compact **MB** mark is used as the browser icon.

## Image curation

Real project captures should be the primary visual proof:
- LibTrack: availability, seat selection, booking
- Swapino: profile, skill discovery, exchange
- Vishrya: assistant/chat, persistence, error states

Generated visuals may support the visual system, but must never pretend to be screenshots, results, or evidence.

### Rejected image note
**Rejected:** a generic AI-generated futuristic dashboard/technology hero.

**Why:** it looked impressive but did not prove anything about my work. It would pull attention away from the real products and make the portfolio feel like a template. The restrained build-loop visual keeps the focus on project evidence.

## Proof still needed
- Real screenshots for each project
- Public demo links where available
- Individual GitHub links
- Any real user-testing observations
- Concrete outcomes/metrics only where documented

No unsupported users, revenue, awards, production status, or performance claims should be added.

## Design decision

The portfolio is deliberately a **frame, not the painting**: the visual system creates consistency and hierarchy while the projects and their evidence remain the main content.
